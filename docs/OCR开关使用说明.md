# 图片自动识别开关使用说明

## 功能说明

机器人提供了**会话级别**的图片自动识别（OCR）功能开关控制：
- ✅ **私聊**：每个私聊可以独立设置是否启用OCR
- ✅ **群聊**：每个群聊可以独立设置是否启用OCR
- ✅ **互不影响**：不同会话的设置互相独立

## 配置方式

### 1. 环境变量配置（全局开关）

在 `.env` 文件中设置全局开关：

```bash
# 全局开启图片识别（默认）
ENABLE_OCR=true

# 全局关闭图片识别
ENABLE_OCR=false
```

**注意**：
- 这是**全局开关**，关闭后所有会话都无法使用OCR
- 修改 `.env` 文件后需要重启机器人才能生效
- 建议保持开启，使用会话级别控制更灵活

### 2. 管理员命令（会话级别控制）

管理员可以使用 `/toggle_ocr` 命令控制**当前会话**的OCR功能：

#### 查看当前状态
```
/toggle_ocr
```

#### 开启图片识别
```
/toggle_ocr on
```

或使用其他别名：
- `/toggle_ocr enable`
- `/toggle_ocr 开启`
- `/toggle_ocr 启用`
- `/toggle_ocr true`
- `/toggle_ocr 1`

#### 关闭图片识别
```
/toggle_ocr off
```

或使用其他别名：
- `/toggle_ocr disable`
- `/toggle_ocr 关闭`
- `/toggle_ocr 禁用`
- `/toggle_ocr false`
- `/toggle_ocr 0`

## 功能效果

### 当前会话开启状态
- ✅ 用户在此会话发送图片时，自动进行 OCR 识别
- ✅ 自动提取订单号、UTR、UPI 等信息
- ✅ 自动查询订单状态
- ✅ 支持支付截图验证

### 当前会话关闭状态
- ❌ 用户在此会话发送图片时，提示"当前会话已关闭图片识别功能"
- ❌ 不会调用 OCR API
- ✅ 节省 OCR API 调用次数和费用
- ✅ 用户仍可使用命令查询（如 `/order`、`/upi`、`/bd` 等）
- ✅ 其他会话不受影响

## 使用场景

### 何时关闭某个会话的 OCR？
1. **特定群组不需要**：某些群聊不需要图片识别功能
2. **测试群组**：测试环境的群聊，避免误识别
3. **成本控制**：限制某些会话的 OCR 使用
4. **临时维护**：某个会话暂时不需要此功能

### 何时开启 OCR？
1. **正常运营**：为用户提供完整的图片识别服务
2. **高峰期**：用户需要快速上传截图查询订单
3. **自动化处理**：减少用户手动输入订单号的工作量

## 典型应用场景

### 场景1：多个群聊，部分需要OCR
```
群聊A（客服群）：开启 OCR - 需要快速识别订单截图
群聊B（测试群）：关闭 OCR - 避免测试数据被识别
私聊C（商户1）：开启 OCR - 正常使用
私聊D（商户2）：关闭 OCR - 该商户只用命令查询
```

### 场景2：临时关闭某个会话
某个群聊暂时不需要OCR功能：
```bash
# 在该群聊中执行
/toggle_ocr off

# 需要时再开启
/toggle_ocr on
```

## 权限要求

只有**管理员**才能使用 `/toggle_ocr` 命令。

管理员配置方式：
1. 在 `.env` 文件中设置 `ADMIN_USER_IDS`
2. 使用 `/myid` 命令查看自己的 Telegram ID
3. 将 ID 添加到 `ADMIN_USER_IDS` 中（多个用逗号分隔）

示例：
```bash
ADMIN_USER_IDS=123456789,987654321
SUPER_ADMIN_ID=123456789
```

## 注意事项

⚠️ **会话级别设置**
- 使用 `/toggle_ocr` 命令的设置是**会话级别的**
- 设置会保存到数据库，重启后依然有效
- 每个会话（私聊/群聊）都有独立的设置
- 新绑定的会话默认开启 OCR

⚠️ **用户体验**
- 关闭某个会话的 OCR 后，该会话用户发送图片会收到提示
- 提示信息会告知用户如何开启（管理员命令）
- 用户仍可使用其他命令查询订单
- 其他会话的用户不受影响

## 相关命令

| 命令 | 说明 | 权限 |
|------|------|------|
| `/toggle_ocr` | 查看/切换 OCR 状态 | 管理员 |
| `/help` | 查看帮助（管理员可看到此命令） | 所有用户 |
| `/broadcast` | 发送广播通知 | 管理员 |
| `/order <订单号>` | 手动查询订单（不依赖 OCR） | 已绑定用户 |
| `/upi <地址>` | 验证 UPI 地址（不依赖 OCR） | 已绑定用户 |
| `/bd <UTR> <订单号>` | 手动补单（不依赖 OCR） | 已绑定用户 |

### 工作流程
1. 用户在某个会话发送图片
2. `photo_handler` 接收图片
3. 获取当前会话的商户信息
4. 检查全局 `settings.ENABLE_OCR` 状态（全局开关）
5. 检查当前会话的 `merchant.enable_ocr` 状态（会话开关）
6. 如果任一关闭，返回相应提示消息
7. 如果都开启，继续 OCR 识别流程
